## Product and safety boundaries

The new public experience uses the reviewed, pinned Scroll Craft engine and its original MIT license from `nateherkai/scroll-craft@0b816225945e45380397d6a0487efa3c98916858`. There is a new Hebrew marketing site, an interactive factual matching demonstration, and a new three-area guest workspace: Today, Leads, Results.

Guest state is local to the current browser (`shuvflow-guest-v1`). It is not a cloud account, is not cross-device synchronization, and is not a replacement for a production clinical-data storage assessment. Twenty initial contacts are fictional, with reserved non-routable email addresses. Guest users can work on local inputs, export CSV, download a full JSON backup, and explicitly confirm restore/reset.

No automatic WhatsApp/email delivery, calendar invitations, payments, invoicing or CRM integration is connected. Copying is not sending; booking and closing do not confirm revenue; the operator must explicitly confirm a received amount. DNC, medical-review and incomplete records cannot enter outreach. No reason means no message.

Existing Supabase clinical data and policies were not mutated during this rebuild. Legacy cloud login/onboarding routes remain separate. Their authentication issue is not claimed to have been repaired; guest access removes the account barrier without weakening authentication or tenant isolation.

## Deployment mechanics

Deployment reused the existing Vercel project. Its three-file build bootstrap fetches the immutable public GitHub application commit, runs `npm ci`, typecheck, tests and `npm run build`, then publishes `source/out` as `site` and writes build-info.json. This is not Git-integrated automatic deployment on each future push: publish an explicit new tested revision through the connected Vercel deployment action and rerun anonymous public acceptance.
